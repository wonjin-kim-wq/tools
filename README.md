# 참코딩

기존 카드·검색·분류 화면과 업로드 요청, 대기 목록, 관리자 검토를 제공하는 Vercel 정적 사이트 + Node API입니다. 데이터와 이미지는 Supabase에 보관합니다.

최근 변경 사항과 카드·캐릭터의 현재 동작 설정은 [작업 기록](WORK_LOG.md)에 정리했습니다.

최종 내용 갱신: 2026-11-03. 운영 사이트는 https://tools-one-nu.vercel.app/ 이며, GitHub `main`에 푸시하면 연결된 Vercel에서 자동 배포합니다. 함수 실행 지역은 서울 `icn1`입니다.

## 현재 화면과 캐릭터 동작

| 항목 | 동작 |
| --- | --- |
| 카드 이동 | 기존 0.8초 이동 애니메이션, 카드별 30ms 순차 지연 유지 |
| 카드 클릭 | 캐릭터 활성화 시 클릭 모션 후 220ms 뒤 상세 화면 열기. 비활성화 시 즉시 열기 |
| 카드 위 커서 | 같은 카드에 500ms 머문 뒤 캐릭터가 카드 오른쪽 위로 이동. 그전까지는 커서를 따라감 |
| 모서리 대기 | 도착하면 눈을 깜빡이며 대기. 카드 이탈 시 다시 커서를 따라가고, 다른 카드에서는 대기 시간을 초기화 |
| 캐릭터 표시 | 마우스·정밀 포인터가 있는 641px 이상 화면에서 토글 설정에 따라 표시 |
| 인기순 | 상위 3개 카드 왼쪽 위에 작은 트로피와 등수 표시 |
| 화면 구성 | 왼쪽 사이드바(로고·검색·카테고리·업로드 요청·앱 개발 요청·관리자 메뉴·캐릭터·로그인). 900px 이하에서는 상단 바와 '메뉴' 펼침 |
| 홍보 배너 | 본문 최상단. 관리자가 지정한 추천 앱을 6초마다 번갈아 표시, 지정한 앱이 없으면 인기 1위 |
| 앱 상세 | 상단 사용하기 버튼(URL 없는 예시 앱은 비활성화) → 정보 줄 **교과 · 카테고리 · 개발자 · 적용 학년** → 스크린샷(캡션 미표시) → 소개 영상 → 설명 → 리뷰 · 제작자의 다른 앱 → 새로운 소식 |
| 카테고리 | 교과 교육·계기 교육·아침활동·교실놀이·기타 |
| 교과 | 국어·수학·사회·과학·영어·도덕·실과(정보)·음악·미술·체육·통합교과·창의적 체험활동·교과 무관 중 여러 개 선택. 새 업로드는 1개 이상 필수 |
| 리뷰 | 평점 없음. 참코딩 회원만 앱마다 1개 작성·수정, 관리자는 숨김 가능 |
| 관리자 로그인 | 헤더 버튼 없음. 회원 로그인 창(로그인 상태면 내 계정 창) 아래 '관리자로 로그인' 버튼 |

업로드 요청 영역에서는 관리자 전용 **요청 검토 · 앱 관리**, **업로드 비밀번호** 메뉴를 표시하지 않습니다. 관리자 로그인 상태로 업로드 요청을 열어도 영역 구분을 유지합니다.

## 주요 파일

| 파일 | 역할 |
| --- | --- |
| `index.html` | 카드·검색·분류·정렬·상세 화면·커서 캐릭터와 인라인 JavaScript |
| `tools.js`, `tools.css` | 회원·업로더·관리자 작업 창, 업로드·대기 목록·검토 화면 |

| `supabase/` | 전용 스키마·시드·마이그레이션 |

## 실행과 검사

```sh
npm test
npm run build
npm run dev
git diff --check
```

`npm run dev`는 `http://127.0.0.1:8741`에서 실행합니다. 실제 API는 아래 환경 변수가 필요합니다. 로컬에 계정을 생성하지 않고 브라우저 검증하려면 `node tests/ui-server.js`를 사용합니다. 이 격리된 메모리 서버는 8742 포트에서 실행하며 테스트용 관리자 `local-admin` / `local-admin-test-only`, 업로더 비밀번호 `local-upload-test-only`를 제공합니다. 테스트 서버와 자격 증명은 배포되지 않습니다.

실제 운영 관리자 계정 생성이나 비밀번호 변경을 테스트 수단으로 사용하지 않습니다. API·권한 변경 시 관련 테스트를 실행하고, 화면 변경 시 해당 동작도 확인합니다.

## 반응 속도 처리

- 작업 창을 먼저 열어 로딩 상태를 보여주고, 이전 화면의 늦은 응답이 현재 화면을 덮어쓰지 않도록 처리합니다.
- 클라이언트 세션 조회는 진행 중 요청을 공유하고 15초 이내 결과를 재사용합니다. 로그인·로그아웃 등 인증 상태 변경 시 무효화합니다.
- 서버 권한은 매 HTTP 요청에서 검사합니다. 관리자 정보의 중복 DB 조회는 한 요청 안에서만 공유합니다.
- 세션의 관리자·회원 확인과 이미지 소유권 확인을 병렬 처리합니다.
- 창 크기 변경에 따른 카드 재배치를 프레임 단위로 묶고, 높이만 바뀔 때 불필요한 재배치를 피합니다.
- 카드 이동 애니메이션과 캐릭터 클릭 모션용 지연은 위 표의 사용자 지정 값을 유지합니다.

## Supabase

`supabase/schema.sql`은 방문 집계 테이블을 포함한 `tools_` 전용 테이블 6개와 `chamcoding-screenshots` 비공개 버킷을 만듭니다. `supabase/seed.sql`은 기존 예시 앱 10개를 추가하며 같은 ID가 있으면 기존 내용을 보존합니다. 기존 프로젝트의 다른 테이블과 인증 설정은 변경하지 않습니다.

현재 기존 `mono` 프로젝트를 공유하므로 참코딩 전용 테이블·저장 공간 범위에서만 작업합니다.

환경 변수는 Vercel **서버 비밀 변수**로 설정합니다. 클라이언트에 키를 넣거나 `NEXT_PUBLIC_` 같은 공개 접두사를 붙이지 않습니다.

| 변수 | 용도 |
| --- | --- |
| `SUPABASE_URL` | Supabase 프로젝트 URL |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 전용 API 키 |
| `SESSION_SECRET` | 충분히 긴 무작위 세션 서명 키 |
| `UPLOAD_PASSWORD` | 연구회 업로더 공통 비밀번호 |
| `ADMIN_SETUP_TOKEN` | 최초 관리자 등록용 무작위 일회성 토큰 |

`tools_admins`에 등록한 사이트 관리자는 Supabase 대시보드 계정과 별개입니다. 최초 등록은 소유자에게 전달하는 `/#setup=…` 링크에서만 가능합니다. 첫 계정이 생성되면 추가 등록은 서버에서 차단됩니다. 관리자 비밀번호는 scrypt와 개별 salt로 해시하며, 로그인 세션은 HttpOnly·Secure·SameSite=Strict 쿠키를 사용합니다. 설정 토큰은 URL fragment에서 읽은 직후 주소 표시줄에서 제거됩니다. 등록이 끝나면 Vercel의 `ADMIN_SETUP_TOKEN`을 제거할 수 있습니다.

## 요청과 검토

- 업로더는 공통 비밀번호로 요청 폼과 전체 요청 상태 목록에 접근합니다. 연락 이메일은 관리자에게만 표시합니다.
- 스크린샷은 1~6장, 클라이언트에서 최대 1800px로 조정하고 서버에서 파일당 2MB와 실제 파일 형식을 검증합니다. 비공개 저장소의 1시간 서명 URL을 통해 보여줍니다.
- 요청은 항상 `pending`으로 저장합니다. 업로더가 승인 상태나 사용 횟수를 보내도 무시합니다.
- 관리자는 앱 정보·스크린샷·설명을 수정하고 승인, 수정 요청, 반려, 공개 중지를 처리합니다. 승인된 앱만 공개 API가 반환합니다.
- 검토 버전이 바뀐 요청은 덮어쓰지 않고 다시 불러오도록 안내합니다.
- 업로드하지 못하고 남은 스크린샷은 비공개 버킷에 남을 수 있습니다. 운영 중 정리할 때 `tools_apps.screenshots`에 참조되지 않는 오래된 `tools_uploads` 경로만 선별합니다.

`npm test`에는 권한 분리, 세션 변조·만료, URL·이미지 검증, 검토 수정과 승인 후 공개, 동시 수정 충돌 테스트가 포함됩니다. 실제 관리자 계정은 테스트 과정에서 생성하지 않습니다.

## 일반 회원 로그인

일반 회원은 Supabase Auth의 이메일·비밀번호 가입과 인증을 사용합니다. 기존 업로더·관리자 쿠키와 분리한 `chamcoding_member` HttpOnly 쿠키를 사용하며 세션 유효시간은 최대 1시간입니다. 비밀번호와 Supabase 토큰은 프런트엔드 응답이나 로컬 저장소에 보관하지 않습니다.

서버가 가입 시 `app_metadata.chamcoding_member`, `app_metadata.chamcoding_content_access`를 설정합니다. 사용자 수정이 가능한 `user_metadata`는 접근 권한으로 사용하지 않습니다. `/api/tools?action=member-content`는 실제 Supabase 사용자 검증과 회원 권한 확인 후 응답합니다. 현재 콘텐츠 목록은 비어 있으며 향후 전용 콘텐츠 API에도 같은 검사를 적용합니다. `chamcoding_content_access=false`로 이용 권한을 중지할 수 있습니다. 일반 회원 자격은 업로드 승인·관리자 권한을 부여하지 않습니다.

Supabase의 이메일 인증 설정과 SMTP 발송 제한을 적용합니다. 운영용 회원가입에는 Supabase의 발송 설정을 확인해야 합니다. 기존 mono 앱의 인증 설정을 일괄 변경하지 않습니다.

대표 썸네일은 업로드한 첫 번째 이미지이며 기존 JSON 스크린샷 구조를 그대로 사용합니다. 대표 사진 교체와 순서 변경은 관리자 수정 화면에서 처리할 수 있습니다.

## 이미지 권장 규격

- 대표 썸네일: **1000×1000px** 정사각형. 카드에서는 `object-fit: cover`로 채우므로 중요한 내용은 중앙에 배치합니다.
- 상세 스크린샷: **900×1020px** 권장. 현재 300×340px 표시 영역에 맞춘 비율입니다. 가로 화면도 원래 비율로 올릴 수 있으며 상세에서는 `object-fit: contain`으로 표시합니다.
- PNG·JPG·WebP를 사용하고 작은 글자는 확대해 주세요. 업로드 시 최대 1800px로 조정하며 서버에서 파일당 2MB를 검사합니다.
- 썸네일을 포함해 최대 6장입니다. 스크린샷 설명 입력은 가능하지만 공개 상세 화면 하단에는 캡션을 표시하지 않습니다.

## 남은 운영 확인

일반 회원가입은 이메일 인증을 유지합니다. SMTP 연결과 실제 인증 메일 발송 확인은 별도 필요한 작업이며, 운영 메일 발송이 검증된 상태로 간주하지 않습니다. 기존 mono 서비스의 인증 설정을 일괄 변경하지 않습니다. 회원 전용 콘텐츠 목록은 현재 비어 있습니다.

## 관리자 화면에서 업로드 비밀번호 변경

관리자 로그인 후 **업로드 비밀번호** 메뉴에서 현재 관리자 비밀번호와 새 업로드 비밀번호(8자 이상), 확인을 입력합니다. `supabase/migrations/20261103_upload_password.sql`을 먼저 적용해야 합니다.

새 업로드 비밀번호는 `tools_admins`의 별도 scrypt 해시·salt로 저장합니다. 첫 변경 전에는 기존 `UPLOAD_PASSWORD` 환경 변수 값을 사용하며, 첫 변경 후에는 DB에 저장된 해시를 사용합니다. 기존 비밀번호는 화면이나 API에서 조회할 수 없습니다. 변경 즉시 기존 업로더 세션을 무효화하며 관리자·일반 회원의 세션에는 영향을 주지 않습니다. 재배포가 필요하지 않고, 이후 배포에서도 DB 설정이 유지됩니다.


## 전체·오늘 방문자 (2026-11-03 추가)

목록 하단에 **전체 방문자**와 **오늘 방문자**를 표시합니다. 사용자 요청에 따라 중복 방문 제외와 화면의 중복 안내 문구는 넣지 않습니다. 페이지를 새로 열거나 새로고침할 때마다 1회 증가하며 로그인·필터·정렬·카드 클릭으로는 증가하지 않습니다. 과거 방문 기록은 소급하지 않고 기능 적용 시점부터 집계합니다.

- DB: 기존 mono 프로젝트의 `tools_visit_total`(누적)·`tools_visit_daily`(일별) 전용 테이블.
- 기존 DB에는 `supabase/migrations/20261103_visits.sql` 적용. 신규 설치용 `supabase/schema.sql`에도 같은 정의 포함.
- 오늘 날짜는 서버에서 `Asia/Seoul` 기준으로 계산합니다. 날짜가 바뀐 뒤 발생하는 방문은 새 날짜에 집계하며 누적 수는 유지합니다.
- `tools_visit_counts(boolean)` RPC가 한 트랜잭션에서 누적·일별 수를 증가시켜 동시 방문 시 덮어쓰기를 방지합니다.
- `POST /api/tools?action=visits`: 페이지 로드 시 1회 호출해 증가 후 수치 반환. 자동 재시도는 하지 않습니다.
- `GET /api/tools?action=visits`: 증가 없이 현재 집계 조회. POST는 기존 동일 출처·JSON 요청 검사를 적용합니다.
- 테이블은 RLS를 활성화하고 브라우저의 anon·authenticated 직접 접근을 차단합니다. 서버 service_role만 테이블·RPC에 접근합니다.
- 방문 집계에 IP·이메일·쿠키 식별자를 저장하지 않습니다. 방문자 수는 실제 고유 인원이 아닌 페이지 방문 횟수입니다.
- 집계 요청은 목록·로그인 조회와 독립적으로 실행해 카드 반응을 지연시키지 않습니다. 실패 시 숫자를 꾸며내지 않고 조회 실패를 표시합니다.
- 검증: 반복 호출 증가·GET 비증가·타 출처 POST 차단 테스트를 포함한 15개 테스트 통과, 빌드·구문·diff 검사 완료.
