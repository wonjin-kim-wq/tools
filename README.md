# 참코딩

기존 카드·검색·분류 화면과 업로드 요청, 내 요청, 관리자 검토를 제공하는 Vercel 정적 사이트 + Node API입니다. 데이터와 이미지는 Supabase에 보관합니다.

최근 변경 사항과 카드·캐릭터의 현재 동작 설정은 [작업 기록](WORK_LOG.md)에 정리했습니다. 작업을 마칠 때마다 `WORK_LOG.md` 맨 위에 날짜별 항목(바뀐 점·확인·남은 일)을 추가하고, 이 README의 관련 절도 함께 고칩니다.

최종 내용 갱신: 2026-11-19 (웹앱 제목과 버튼 상단 정렬). 운영 사이트는 https://www.chamssaem.kr/ (기존 https://tools-one-nu.vercel.app/ 는 www.chamssaem.kr로 자동 이동)이며, GitHub `main`에 푸시하면 연결된 Vercel에서 자동 배포합니다. 함수 실행 지역은 서울 `icn1`입니다.

## 업로드 요청

사이드바의 **업로드 요청**에서 다음 세 가지 방법을 고를 수 있습니다. 이메일을 인증한 참코딩 회원이라면 공통 비밀번호 없이 요청할 수 있으며, 접수된 앱은 관리자 승인 후 공개됩니다.

1. **에이전트 요청**(기본): 로그인하고 **토큰 발급**을 누르면 **설정 프롬프트 복사** 버튼이 활성화됩니다. 복사한 내용을 Claude Code나 Codex 채팅에 붙여 넣으세요. 이미 발급된 토큰으로 연결하려면 저장해 둔 값을 **토큰 붙여 넣기** 칸에 입력하세요. 연결이 끝나면 예시 문장에 앱 주소를 넣어 등록을 요청합니다. 준비한 내용과 본인 제작 확인에 동의하면 접수됩니다.
2. **프롬프트 요청**: 앱 한 개용 또는 여러 개용 프롬프트를 복사해 AI에게 소개 문구와 스크린샷 준비를 맡깁니다. 준비한 자료는 직접 업로드 탭에서 확인한 뒤 보냅니다.
3. **직접 업로드**: 앱 한 개를 입력하거나 여러 앱용 카드를 추가해 한 번에 제출합니다.

로그인 후 **내 요청 보기**에서 직접 제출한 요청과 MCP 요청의 상태·검토 메모를 함께 확인할 수 있습니다.

### 에이전트 연결 (MCP)

연결 주소는 `https://www.chamssaem.kr/mcp`입니다. Claude 앱의 사용자 지정 커넥터에는 URL을 추가해 공개 앱을 볼 수 있습니다.

- 계정당 활성 토큰 1개를 새로 발급할 수 있습니다. 같은 토큰을 여러 에이전트에서 사용할 수 있습니다. 이전에 여러 토큰을 발급한 계정은 기존 연결을 유지하며, 활성 토큰이 남아 있으면 추가 발급을 할 수 없습니다. 업로드 요청 창 맨 아래 **MCP 연결 기록**에 서버 주소, 토큰 일부, 발급일과 마지막 사용일을 표시합니다. 토큰 전체 값은 발급한 창에서 복사할 수 있으며 서버에는 SHA-256 해시를 저장합니다. 토큰을 잃어버렸다면 연결 기록에서 폐기하고 다시 발급할 수 있습니다. 폐기하면 해당 토큰을 쓰는 모든 연결에서 앱 등록이 중단됩니다.
- 공개 도구는 `list_options`, `search_apps`, `get_app`입니다. 등록 도구는 `upload_screenshot`, `register_app`, `list_my_apps`, `update_app`이며 회원 Bearer 토큰이 필요합니다.
- 스크린샷은 PNG·JPG·WebP, 장당 2 MB, 1~6장입니다. 에이전트가 로컬 이미지의 base64를 `upload_screenshot`에 전달합니다. 직접 도구 입력이 어려우면 로컬 스크립트에서 파일을 읽어 `Content-Type: application/json`과 Bearer 인증 헤더를 붙이고 `/mcp`로 `{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"upload_screenshot","arguments":{"data_base64":"…","caption":"시작 화면"}}}`을 POST할 수 있습니다. 토큰과 이미지 원문을 로그에서 제외하세요.
- `register_app`은 먼저 `dry_run: true`로 검증합니다. 30분 안에 같은 앱 정보와 `confirmation_id`, `confirm_own_work: true`를 보내면 승인 대기로 접수됩니다. 같은 회원이 같은 주소를 다시 제출하면 기존 요청을 반환합니다. 직접 제출한 요청은 웹의 **내 요청**에 표시됩니다. `update_app`은 승인 대기·수정 요청에만 적용되며 `list_my_apps`가 반환하는 최신 `version`이 필요합니다.
- 토큰당 시간당 스크린샷 업로드 36회, 등록 검증 24회, 등록 12회, 수정 12회까지입니다.

기존 DB에서 이 기능을 사용하려면 [MCP 마이그레이션](supabase/migrations/20261118_mcp.sql)이 적용되어 있어야 합니다. 운영 DB는 참코딩 전용 프로젝트 `chamssaem`을 사용합니다. 계정당 토큰 1개 제한을 배포하기 전에 [추가 발급 제한 마이그레이션](supabase/migrations/20261119000000_single_mcp_token_per_member.sql)을 적용하세요. 새 DB에는 최신 [스키마](supabase/schema.sql)를 사용합니다. MCP는 기존 Supabase·세션 환경 변수를 사용합니다. 로컬 주소는 `npm run dev`의 `http://127.0.0.1:8741/mcp`입니다. `node tests/ui-server.js`에서는 운영 데이터와 분리한 테스트 회원과 대기열로 흐름을 검증할 수 있습니다.

## 실행과 검사

```sh
npm test
npm run build
npm run dev
git diff --check
```

`npm run dev`는 `http://127.0.0.1:8741`에서 실행합니다. 실제 API는 아래 환경 변수가 필요합니다. 로컬에 계정을 생성하지 않고 브라우저 검증하려면 `node tests/ui-server.js`를 사용합니다. 이 격리된 메모리 서버는 8742 포트에서 실행하며 테스트용 관리자 `local-admin` / `local-admin-test-only`, 테스트용 회원 `member@local.test` / `local-member-test-only`를 제공합니다. 테스트 서버와 자격 증명은 배포되지 않습니다.

실제 운영 관리자 계정 생성이나 비밀번호 변경을 테스트 수단으로 사용하지 않습니다. API·권한 변경 시 관련 테스트를 실행하고, 화면 변경 시 해당 동작도 확인합니다.

## 반응 속도 처리

- 작업 창을 먼저 열어 로딩 상태를 보여주고, 이전 화면의 늦은 응답이 현재 화면을 덮어쓰지 않도록 처리합니다.
- 클라이언트 세션 조회는 진행 중 요청을 공유하고 15초 이내 결과를 재사용합니다. 로그인·로그아웃 등 인증 상태 변경 시 무효화합니다.
- 서버 권한은 매 HTTP 요청에서 검사합니다. 관리자 정보의 중복 DB 조회는 한 요청 안에서만 공유합니다.
- 세션의 관리자·회원 확인과 이미지 소유권 확인을 병렬 처리합니다.
- 창 크기 변경에 따른 카드 재배치를 프레임 단위로 묶고, 높이만 바뀔 때 불필요한 재배치를 피합니다.
- 카드 이동 애니메이션과 캐릭터 클릭 모션용 지연은 위 표의 사용자 지정 값을 유지합니다.

## Supabase

`supabase/schema.sql` 하나로 `tools_` 전용 테이블 12개, 함수 7개, 트리거 4개와 `chamcoding-screenshots` 비공개 버킷을 만듭니다(지금까지의 마이그레이션이 모두 들어 있음). `supabase/seed.sql`은 기존 예시 앱 10개를 추가하며 같은 ID가 있으면 기존 내용을 보존합니다.

참코딩은 2026-11-18부터 전용 Supabase 프로젝트(`chamssaem`, 참조 ID `ivraxclebyfkyimirole`, 서울 ap-northeast-2)를 씁니다. 이전에는 quiz-games(옛 이름 `mono`) 프로젝트를 함께 썼습니다. 옮긴 방법과 대조 도구는 아래 'DB 분리'를 참고합니다.

환경 변수는 Vercel **서버 비밀 변수**로 설정합니다. 클라이언트에 키를 넣거나 `NEXT_PUBLIC_` 같은 공개 접두사를 붙이지 않습니다.

## 요청과 검토

- `upload`, `submit`, `queue`는 이메일이 인증된 참코딩 회원이 사용합니다. 직접 요청에도 서버가 제출자의 `member_id`를 기록합니다. 연락 이메일은 관리자에게만 표시됩니다.
- 관리자는 별도 관리자 세션으로 전체 요청을 조회(`queue&scope=admin`)하고 검토 중에 이미지를 추가(`upload&scope=admin`)할 수 있습니다. 공통 비밀번호로 접수해 제출 계정이 없는 기존 요청은 관리자 목록에 계속 남습니다.
- 회원 한 명이 같은 주소로 보낸 요청은 한 건만 유지합니다. 직접 제출·일괄 제출은 합쳐서 회원당 시간당 요청 12회, 사진 36장까지 보낼 수 있습니다.
- 스크린샷은 1~6장, 클라이언트에서 최대 1800px로 조정하고 서버에서 파일당 2MB와 실제 파일 형식을 검증합니다. 비공개 저장소의 1시간 서명 URL을 통해 보여줍니다.
- 요청은 공개 권한과 학생 개인정보 확인을 거쳐 `pending`으로 저장합니다. 회원이 보낸 승인 상태와 사용 횟수는 무시합니다.
- 관리자는 앱 정보·스크린샷·설명을 수정하고 승인, 수정 요청, 반려, 공개 중지를 처리합니다. 승인된 앱만 공개 API가 반환합니다.
- 검토 버전이 바뀐 요청은 덮어쓰지 않고 다시 불러오도록 안내합니다.
- 업로드하지 못하고 남은 스크린샷은 비공개 버킷에 남을 수 있습니다. 운영 중 정리할 때 `tools_apps.screenshots`에 참조되지 않는 오래된 `tools_uploads` 경로만 선별합니다.

`npm test`에는 권한 분리, 세션 변조·만료, URL·이미지 검증, 검토 수정과 승인 후 공개, 동시 수정 충돌 테스트가 포함됩니다. 실제 관리자 계정은 테스트 과정에서 생성하지 않습니다.

## 일반 회원 로그인

상단의 **로그인** 버튼으로 회원 로그인 창을 엽니다. 로그인하면 같은 자리에 사람 모양 **프로필** 버튼이 표시되며, 누르면 내 계정 창이 열립니다.

일반 회원은 Supabase Auth의 이메일·비밀번호 가입과 인증을 사용합니다. 관리자 쿠키와 분리한 HttpOnly 쿠키 두 개를 씁니다. `chamcoding_member`(접근 토큰, 최대 59분)와 `chamcoding_member_refresh`(갱신 토큰, `Path=/api`, 14일)입니다. 접근 토큰이 끝나면 서버가 갱신 토큰으로 새로 받아 1시간마다 로그아웃되지 않습니다. 회원 로그아웃은 쿠키를 지우고 Supabase 세션도 끊습니다. 비밀번호와 Supabase 토큰은 프런트엔드 응답이나 로컬 저장소에 보관하지 않습니다.

- **회원 표시 복구**: 가입 도중 권한 저장에 실패했거나 대시보드에서 직접 만든 계정은 비밀번호 로그인이나 메일 링크로 본인이 확인되면 참코딩 회원(`chamcoding_member`)으로 연결됩니다. 관리자가 `chamcoding_member=false`로 막은 계정은 연결하지 않습니다.
- **메일 링크**: 인증·재설정 메일은 모두 허용 목록에 있는 `https://www.chamssaem.kr/?email-confirmed=1`로 돌아옵니다. 화면은 주소 해시의 토큰을 `member-link`로 서버 쿠키에 옮기고 주소에서 바로 지웁니다. `type=recovery`면 새 비밀번호 화면을, 만료·오류면 다시 받기 안내를 보여줍니다.
- **API**: `member-signup`·`member-login`·`member-logout`·`member-resend`(인증 메일 다시 받기)·`member-recover`(비밀번호 찾기)·`member-link`(메일 링크 토큰을 쿠키로)·`member-password`(로그인 상태에서 비밀번호 변경). 다시 받기·찾기는 가입 여부를 드러내지 않도록 같은 안내를 돌려줍니다.
- **요청 제한**: 학교처럼 여러 교사가 같은 공인 IP를 쓰므로 IP 제한은 넉넉히, 이메일별 제한은 촘촘히 둡니다. 가입 IP 60회·이메일 5회/시간, 로그인 IP 100회·이메일 10회/15분, 다시 받기·찾기 IP 30회·이메일 3회/시간.
- **오류 안내**: Supabase 오류 코드(약한 비밀번호, 유출 비밀번호, 잘못된 주소, 메일 발송 제한 등)를 각각의 안내로 바꾸고, JSON이 아닌 게이트웨이 오류도 500 대신 503 안내로 돌려줍니다.
- 옛 주소 `tools-one-nu.vercel.app`는 `vercel.json`에서 `https://www.chamssaem.kr`로 영구 이동합니다.

서버가 가입 시 `app_metadata.chamcoding_member`, `app_metadata.chamcoding_content_access`를 설정합니다. 사용자 수정이 가능한 `user_metadata`는 접근 권한으로 사용하지 않습니다. `/api/tools?action=member-content`는 실제 Supabase 사용자 검증과 회원 권한 확인 후 응답합니다. 현재 콘텐츠 목록은 비어 있으며 향후 전용 콘텐츠 API에도 같은 검사를 적용합니다. `chamcoding_content_access=false`로 이용 권한을 중지할 수 있습니다. 이메일을 인증한 일반 회원은 콘텐츠 이용 권한 설정과 별개로 업로드를 요청할 수 있습니다. 업로드 승인은 관리자만 할 수 있습니다.

이메일 인증은 켜져 있고, 메일은 새 프로젝트의 Gmail SMTP로 보냅니다(위 'DB 분리' 참고). Supabase 쪽 비밀번호 최소 길이는 6자이지만 참코딩 서버와 화면이 8자 이상을 요구합니다.

대표 썸네일은 업로드한 첫 번째 이미지이며 기존 JSON 스크린샷 구조를 그대로 사용합니다. 대표 사진 교체와 순서 변경은 관리자 수정 화면에서 처리할 수 있습니다.

## 이미지 권장 규격

- 대표 썸네일: **1000×1000px** 정사각형. 카드에서는 `object-fit: cover`로 채우므로 중요한 내용은 중앙에 배치합니다.
- 상세 스크린샷: **900×1020px** 권장. 현재 300×340px 표시 영역에 맞춘 비율입니다. 가로 화면도 원래 비율로 올릴 수 있으며 상세에서는 `object-fit: contain`으로 표시합니다.
- PNG·JPG·WebP를 사용하고 작은 글자는 확대해 주세요. 업로드 시 최대 1800px로 조정하며 서버에서 파일당 2MB를 검사합니다.
- 썸네일을 포함해 최대 6장입니다. 스크린샷 설명 입력은 가능하지만 공개 상세 화면 하단에는 캡션을 표시하지 않습니다.

새 기능이 포함된 코드를 배포하기 전에 위 마이그레이션이 먼저 적용되어 있어야 합니다. 기존 운영 앱의 교과는 비어 있으므로 관리자 화면에서 앱마다 교과를 골라 저장합니다.

격리 UI 서버에 예시 앱을 넣어 확인하려면 `UI_FIXTURE_SEED=1 node tests/ui-server.js`로 실행합니다. 이때 테스트 회원 `member@local.test` / `local-member-test-only`로 리뷰를 확인할 수 있으며, 이 계정은 격리 서버에서만 동작합니다.

## 일괄 업로드와 준비용 프롬프트

- **업로드 요청 → 직접 업로드 → 여러 앱 일괄 업로드**에서 앱마다 카드를 하나씩 추가합니다(최대 12개). 앱마다 대표 썸네일을 포함해 사진 1~6장, 합계 최대 36장이며 첫 사진이 대표 썸네일입니다.
- 연락 이메일과 공개 권한·개인정보 확인은 모든 카드에 함께 적용됩니다. 앱마다 한 건씩 관리자 검토 대기열에 접수되며, 중간에 실패한 카드를 고쳐 다시 보내면 이미 보낸 카드는 건너뜁니다.
- **프롬프트 요청** 탭에서 한 개용·일괄용 프롬프트를 복사할 수 있습니다. 앱 주소를 넣어 에이전트나 브라우저 사용이 가능한 AI에 주면 캡처와 폼용 초안 작성을 요청할 수 있습니다. 초안과 사진은 직접 업로드에서 확인하고 제출합니다.

기존 공통 업로드 비밀번호와 관리 화면은 폐지했습니다. `UPLOAD_PASSWORD`는 더 이상 읽지 않으며, DB의 과거 비밀번호 설정 칸은 기존 배포와의 호환을 위해 건드리지 않습니다.

## 전체·오늘 방문자 (2026-11-03 추가)

목록 하단에 **전체 방문자**와 **오늘 방문자**를 표시합니다. 사용자 요청에 따라 중복 방문 제외와 화면의 중복 안내 문구는 넣지 않습니다. 페이지를 새로 열거나 새로고침할 때마다 1회 증가하며 로그인·필터·정렬·카드 클릭으로는 증가하지 않습니다. 과거 방문 기록은 소급하지 않고 기능 적용 시점부터 집계합니다.

- DB: 기존 mono 프로젝트의 `tools_visit_total`(누적)·`tools_visit_daily`(일별) 전용 테이블.
- 기존 DB에는 `supabase/migrations/20261103_visits.sql` 적용. 신규 설치용 `supabase/schema.sql`에도 같은 정의 포함.
- 오늘 날짜는 서버에서 `Asia/Seoul` 기준으로 계산합니다. 날짜가 바뀐 뒤 발생하는 방문은 새 날짜에 집계하며 누적 수는 유지합니다.
- `tools_visit_counts(boolean)` RPC가 한 트랜잭션에서 누적·일별 수를 증가시켜 동시 방문 시 덮어쓰기를 방지합니다.
- `POST /api/tools?action=visits`: 페이지 로드 시 1회 호출해 증가 후 수치 반환. 자동 재시도는 하지 않습니다.
- `GET /api/tools?action=visits`: 증가 없이 현재 집계 조회. POST는 기존 동일 출처·JSON 요청 검사를 적용합니다.
- 테이블은 RLS를 활성화하고 브라우저의 anon·authenticated 직접 접근을 차단합니다. 서버 service_role만 테이블·RPC에 접근합니다.
- 방문 집계에 IP·이메일·쿠키 식별자를 저장하지 않습니다. 방문자 수는 실제 고유 인원이 아닌 페이지 방문 횟수입니다.
- 집계 요청은 목록·로그인 조회와 독립적으로 실행해 카드 반응을 지연시키지 않습니다. 실패 시 숫자를 꾸며내지 않고 조회 실패를 표시합니다.
- 검증: 반복 호출 증가·GET 비증가·타 출처 POST 차단 테스트를 포함한 15개 테스트 통과, 빌드·구문·diff 검사 완료.
